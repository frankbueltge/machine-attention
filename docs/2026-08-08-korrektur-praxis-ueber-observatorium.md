# Korrektur: Die Praxis über dem Observatorium

**Datum:** 2026-08-08 (Abend nach Launch) · **Anlass:** Franks Feedback (`~/Downloads/feedback.md`)
· **Status:** Richtungsdokument, von Frank zu bestätigen

## Der Befund, akzeptiert

Die V0 beantwortet die Frage „Kann eine Maschine einen vorgegebenen öffentlichen Datenstrom
zuverlässig überwachen und daraus autonom verifizierte Cases erzeugen?" — Franks eigentliche
Frage ist aber: **„Kann eine Maschine selbst eine relevante investigative und künstlerische
Praxis entwickeln, indem sie maschinelle Aufmerksamkeit, Skalierung, Persistenz und
Computation ausnutzt?"** Die V0 hat der Maschine beim entscheidenden Akt — der
Problemfindung — fast keine Intelligenz gegeben und verlangt zugleich am Gate einen
machine-scale advantage, für den sie ihr die Mittel (Historie, Quellenvielfalt, Gedächtnis)
vorenthält. Ergebnis der ersten Nacht, konsequent: sieben Ablehnungen, u. a. mit der
Begründung „equally visible to any human reader of the journal". Das Gate hat recht — gegen
die eigene Architektur.

**Konsequenz (Feedback, übernommen): The State Before the Interface wird Project 001
einer größeren machine investigative practice — nicht die Praxis selbst.** Nichts wird
gelöscht; das Observatorium läuft unverändert weiter (E0, nächtlich). Das epistemische
Substrat — Originalbytes+SHA-256, append-only, Claims/Evidence-Trennung, Corrections,
Nullresultate, Autonomie-Trace, keine Persona, Kosten-/Eskalationsgrenzen, deterministische
öffentliche Rekonstruktion — ist exakt das Fundament, auf dem die Praxis glaubwürdig wird.

## Die fehlende Ebene — minimale Architektur, nicht Plattform

Leitsatz aus dem Feedback: **„Baue nicht groß — aber baue offen."** Drei Schichten:

### 1. Source ecology (statt „eine Quelle")

- **Delegation-Charter ersetzt Eskalation E-5:** Innerhalb der Klasse *öffentlich,
  login-frei, kostenfrei, personenfrei* darf die Maschine selbst Quellen **entdecken,
  vermessen (Go/No-Go-Protokoll je Quelle, Muster dataset-hub), Adapter schreiben,
  historische Bestände laden, Quellen verwerfen**. Eskalation nur noch: Login/Paywall,
  bezahlte Daten, personenbezogene Register, aktive Erhebung (Scraping-Grauzonen).
- **Historie ist Beobachtungsmaterial, kein Backfill:** Das No-Backfill-Invariant betrifft
  die eigenen Protokolle (kein rückdatierter Eintrag), nicht das Laden öffentlicher
  Historie. Die TED-Bulk-Historie (Millionen Records, mehrere Jahre) ist der erste echte
  machine-scale-Bestand — erst mit ihr kann das Gate-Kriterium „machine-scale advantage"
  überhaupt fair erfüllt werden.
- Jede Quellen-Aufnahme/-Verwerfung ist ein committeter, begründeter Vorgang im Register.

### 2. Discovery (hier gehört die Intelligenz hin)

- **Nächtlicher bounded Discovery-Pass mit Modell** (Abo-Token, Kosten/Tokens im
  Autonomie-Trace): liest die Akkumulation, sucht Differenzen jenseits der vier
  regelbasierten Trigger — unerwartete Korrelation, Klassifikations-Mismatch,
  Claim/Data-Widerspruch, cross-register absence, semantic drift, institutionelle
  Asymmetrie, fehlender erwarteter Record, emergenter Cluster …
- **Die Maschine darf neue Differenzarten vorschlagen:** als committete *sensor proposals*
  (Definition + Testregel + erwartete Falsifikation). Ein Proposal wird zum stehenden
  Sensor, wenn es sich an realen Daten bewährt; die Beförderung ist ein begründeter Commit.
- Das Sechs-Kriterien-Gate bleibt — aber die Maschine bekommt vorher die Mittel, es ehrlich
  zu bestehen.

### 3. Investigation ↔ Computation ↔ Form

- Case Mode darf **neue Datenräume öffnen** (im Rahmen des Charters), Code erzeugen,
  Hypothesen wechseln — und **Darstellung als Untersuchungsschritt** bauen: eine
  Zwischenform (Karte, Zeitfaltung, Simulation) darf neue Beobachtungen erzeugen, die in
  die Analyse zurückfließen (`analysis → form → new observation → new analysis`).
- Ergebnisse dürfen sein: dataset, instrument, living observatory, interactive work,
  counter-map, simulation, report, tool — **oder nichts.** „Form aus Befund" bleibt; neu
  ist, dass Form nicht erst am Ende vorkommen darf.

## Public dramaturgy ist Teil des Kernsystems

Übernommen als gleichrangige Anforderung neben Architektur und Methode:

- **Vier Tiefen: ATTRACT → ENTER → INVESTIGATE → VERIFY.** Depth on demand — Evidence ist
  unendlich, Aufmerksamkeit nicht. Die tiefste Ebene bleibt die volle Provenienz.
- **Machine Stage / Foyer auf frankbueltge.de:** die laufende Aufmerksamkeit der Maschine
  als wahrnehmbarer Zustand (attention, memory, rejection, doubt, correction) — kein
  Dashboard, keine Statuspage. **Jede sichtbare Zahl ist ein echter Systemzustand** — auch
  und gerade, wenn der ehrliche Zustand klein ist („NO INVESTIGATION IS OPEN. The machine
  has rejected everything it has seen so far.").
- **Exhibition Mode von Anfang an:** Fullscreen/Terminal, Attract-Loop, Touch+Maus,
  Rückkehr bei Inaktivität, Lesbarkeit auf Distanz, QR-Handoff, kein Login, keine
  Sackgassen. Web und Ausstellung teilen denselben Kern.
- **Textdisziplin auf den öffentlichen Ebenen:** one sentence, one phenomenon, one action.
- **Visuelle Sprache aus der Epistemologie** (difference, absence, trace, uncertainty,
  accumulation, correction) — ausdrücklich keine AI-Ästhetik-Klischees (Neon, HUD,
  Partikel). Noch keine finale Sprache: erst 2–3 Prototypen an realen Daten (heute: A
  „Machine Stage", B „Werk-Einstieg SBTI"), Frank entscheidet die Richtung.

## Was heute ausdrücklich NICHT passiert

Kein Plattform-Bau, keine finale visuelle Sprache, kein Umbau des laufenden Observatoriums
(E0 läuft als Project 001 weiter), keine neuen Personas (die Praxis bleibt Apparat, nicht
Figur), kein Namensbeschluss für die Praxis (Franks Entscheidung).

## Offene Entscheidungen (Frank)

1. Prototyp-Richtung A/B (oder Elemente beider) als Grundlage der öffentlichen Bühne.
